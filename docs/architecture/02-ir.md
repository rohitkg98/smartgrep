# IR — Intermediate Representation

**File:** `src/ir/types.rs`

The IR is the contract between parsers and the index builder. A parser reads source code and produces an `Ir`. The index builder reads that `Ir` and knows nothing about how it was produced — whether from Rust, Java, Go, TypeScript, or Python.

## The top-level type

```rust
pub struct Ir {
    pub symbols: Vec<Symbol>,
    pub dependencies: Vec<Dependency>,
}
```

That's it. Two flat lists. No trees, no nesting, no language-specific fields.

## Symbol

A `Symbol` is any named structural unit in source code.

```rust
pub struct Symbol {
    pub name: String,              // short name: "parse_file"
    pub qualified_name: String,    // fully qualified: "parser::rust::parse_file"
    pub kind: String,              // language-native: "fn", "func", "class", "def", ...
    pub loc: SourceLoc,            // file, line, col
    pub visibility: Visibility,    // Public, Crate, Private
    pub signature: Option<String>, // full signature string
    pub parent: Option<String>,    // enclosing type (for methods)
    pub attributes: Vec<String>,   // #[derive(...)], @Override, @Injectable(), ...
    pub fields: Vec<Field>,        // struct/enum fields
    pub params: Vec<Param>,        // function parameters
    pub return_type: Option<String>,
}
```

`kind` is a plain string holding the language's own keyword — a Go function is `func`, a Python function is `def`, a Java interface is `interface`, a Rust trait is `trait`. There is no shared enum. Code that needs categories ("is this a function?") uses the helpers in `src/ir/kinds.rs` (`FUNCTION_KINDS`, `TYPE_KINDS`, `is_callable_kind`, ...). See [08 — Language-native vocabulary](08-language-native-vocabulary) for the full table and rationale.

`Visibility` is `Public`, `Crate`, or `Private`. `Symbol::new(name, qualified_name, kind, loc, visibility)` fills the optional fields with defaults.

`SourceLoc` is just a file path plus line and column number.

## Dependency

A `Dependency` is a directed edge from one symbol to another.

```rust
pub struct Dependency {
    pub from_qualified: String, // qualified name of the source symbol
    pub to_name: String,        // name of the target (may not be qualified)
    pub kind: DepKind,          // how the dependency arises
    pub loc: SourceLoc,         // where in source it appears
}
```

`DepKind` covers: `Import`, `Call`, `TypeRef`, `Implements`, `FieldType` (displayed as `import`, `call`, `type_ref`, `implements`, `field_type`).

Parsers emit three of them:

- `Import` — every language; `to_name` is the imported path as written (Rust grouped `use a::{B, C}` is split per leaf). TypeScript records one import per imported name as `<module>/<Name>` (`import { User } from '../models'` → `../models/User`); namespace and side-effect imports keep the bare module.
- `Implements` — Rust `impl Trait for T`, Java/TS `extends`/`implements`, Python base classes.
- `Call` — one per distinct callee per function/method body, `from_qualified` = the enclosing function or method. Static/module-qualified callees keep their path (`Foo::new`, `fmt.Errorf`, `os.path.join`, `Collections.sort`); calls on an instance receiver keep only the method name (`self.save()` → `save`), since receivers can't be resolved without types. Macros (Rust) and builtins (Go `make`, `len`, ...) are skipped; closures and lambdas count toward their enclosing function.

`TypeRef` and `FieldType` are defined but not yet produced.

## Why a flat list instead of a tree?

Source code is hierarchical (modules contain functions, impls contain methods). The IR flattens everything. This makes the index builder simple — it just iterates over slices — and makes queries uniform. Hierarchy is preserved through the `parent` field on `Symbol` and `from_qualified` / `to_name` on `Dependency`.

## The contract in practice

```
Parser produces:          Index builder sees:
  Ir {                      for sym in ir.symbols { ... }
    symbols: [...],         for dep in ir.dependencies { ... }
    dependencies: [...],
  }
```

The builder does not import any parser module. The parsers do not import any index module. They share only `src/ir/` (`types.rs` for the data, `kinds.rs` for kind classification).
